# S09 Shizuku launcher (optional, hands-free after reboot)

Depends on: S07, S08. Branch: step/S09-<name>.

Goal: Let the Host app start the same server through Shizuku so the old phone can come back after a reboot without the viewer.

## Prompt

```text
Follow AGENTS.md. Step S09, branch step/S09-shizuku. Work in :launcher-shizuku and :app-host. Read docs/product-requirements.md (L5, RQ-17) and docs/security.md.

1. Add the Shizuku API and provider dependencies. Check the current version and the licence text of each artifact and record both in docs/dependencies.md before using them.
2. Implement ShizukuLauncher : ServerLauncher with states NotInstalled, NotRunning, PermissionNeeded, Ready. Request permission with the Shizuku API; listen for binder received and dead events.
3. Run the server through a UserService (not the deprecated newProcess): create ServerUserService that calls ServerRunner (in :server-core) in the privileged shell process. Remember a UserService process is not a normal app process: no Application Context, no registerReceiver, no ContentResolver. Make ServerRunner depend on none of those; add a test that the :server-core API surface used here is Context-free. Implement the destroy method so the server shuts down cleanly.
4. Authentication: the Host app supplies the PAIRING_SECRET from its Keystore-backed store through the UserService binder; never through argv.
5. Advertise the running server through NsdManager as _velocast._tcp with a TXT record (device id, protocol version); the viewer prefers discovery results over stored IPs.
6. Host status: show Shizuku state and the exact next action; offer links to Shizuku guidance in the app; never block the ADB route.
7. After boot, wait for the Shizuku binder with a timeout and back-off; start the server once available; surface the result in the boot status log.
Tests: launcher state machine with a fake Shizuku facade; ServerRunner Context-free test; discovery record encode and decode.
Definition of done: :launcher-shizuku:check and :app-host:check pass; owner device test plan in the PR; summary per AGENTS.md.
```

## Acceptance criteria

- With Shizuku running, the Host app starts the server after boot and the viewer connects with no ADB step.
- Missing, stopped or permission-denied Shizuku is detected and explained; no crash.
- Licences and versions of the Shizuku libraries recorded in docs/dependencies.md.

## Owner checks

- Install Shizuku on the old phone, start it by wireless debugging, reboot, and check the Host app status and the viewer.
