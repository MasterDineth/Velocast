# S06 Session security: pairing secret, key derivation and AEAD

Depends on: S02, S03. Branch: step/S06-<name>.

Goal: Authenticated, encrypted sessions with secrets stored safely on both phones.

## Prompt

```text
Follow AGENTS.md. Step S06, branch step/S06-security. Work in :protocol (crypto interfaces and framing), :server-core and :client-core (wiring). Read docs/findings.md (SEC-01, SEC-02) and docs/protocol.md.

Design (write it to docs/security.md first, then implement):
- Auth modes: SESSION_SECRET (256-bit random, created per session by the viewer and delivered to the server on stdin when it launches the server over ADB) and PAIRING_SECRET (256-bit random created by the viewer during Prepare and stored in the viewer and the Host app; used when the Host app starts the server through Shizuku or root).
- Handshake: client nonce and server nonce from HELLO and SERVER_HELLO; the proof is HMAC-SHA256 over a transcript hash that includes protocol version, capabilities and both nonces. Constant-time comparison. Failed attempts are rate-limited by SessionGuard.
- Keys: HKDF-SHA256 (RFC 5869) from the secret and nonces to two directional 256-bit keys. Use a vetted library or javax.crypto primitives only; do not implement block ciphers or hashes yourself.
- Framing: AES-256-GCM per frame with a 96-bit counter nonce per direction (4-byte direction prefix + 8-byte counter), header bytes as associated data, strict counter monotonicity (reject replay and reordering), rekey before 2^32 frames.
- Storage: viewer and Host keep secrets in files encrypted by an AES key held in the Android Keystore (use current non-deprecated AndroidX APIs or direct Keystore use); never in SharedPreferences plaintext, logs, backups (disable allowBackup for them) or screenshots.
Implement Authenticator, SessionCipher and KeyStore interfaces in :protocol (pure JVM, tests with HKDF RFC vectors and AEAD known-answer tests), Keystore implementations in the apps/cores, and wire them into SessionGuard and the client handshake.
Negative tests: wrong secret, replayed frame, truncated frame, reordered frames, tampered header, nonce reuse attempt. Add a redaction helper used by the Logger so secrets cannot be logged.
Definition of done: all tests pass; docs/security.md describes threat model, key lifecycle and rotation; summary per AGENTS.md.
```

## Acceptance criteria

- An unauthenticated or wrongly keyed client receives nothing and cannot affect an active session.
- Replayed, reordered or modified frames fail authentication.
- RFC test vectors pass for HKDF; AEAD uses unique nonces per direction.
- No secret appears in logs, crash reports or diagnostics output.
