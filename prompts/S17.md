# S17 Release engineering and documentation

Depends on: S15, S16. Branch: step/S17-<name>.

Goal: Signed, minified, reproducible releases with accurate documentation and a privacy-respecting listing.

## Prompt

```text
Follow AGENTS.md. Step S17, branch step/S17-release. Read docs/findings.md (BLD-02, BLD-03, DOC-01, DOC-02, SEC-08).

1. Enable R8 and resource shrinking for both apps. Write keep rules for the reflection-based hidden-API shims in :server-core and for the Shizuku classes. Build the server as a dex jar from the minified code path and verify it runs on a device by the spike script. Add a test that fails if a keep rule regresses.
2. Signing: release signing config reading from environment variables or CI secrets; never commit keys. Version name and code derived from git tags. Add a reproducible-build check (build twice, compare hashes) where feasible and document anything that cannot be reproducible.
3. Release workflow (.github/workflows/release.yml): on a version tag build, run check, produce signed viewer and host APKs, the server jar, SHA-256 checksums and an SBOM; attach to a GitHub Release with generated notes.
4. Documentation: README (accurate), docs/user-guide.md (setup, Prepare, rescue, reboot recovery, FAQ), docs/troubleshooting.md keyed to the error catalogue, docs/privacy.md and an in-app Privacy and Licences screen listing third-party licences, SECURITY.md with disclosure process, CHANGELOG.md.
5. Metadata for F-Droid style distribution (fastlane layout) and a short store description; keep Google Play out of scope but add docs/play-policy-notes.md listing the policy areas to review (accessibility, foreground service types, local network, device access).
6. Compatibility: run the full smoke tests on an Android 17 preview image if available, keep targetSdk 36, and write docs/targeting-37.md with the local-network permission and other expected changes.
Definition of done: a dry-run release from a tag in a fork produces the expected artefacts; all docs reviewed against the code; summary per AGENTS.md.
```

## Acceptance criteria

- Tagged build produces signed APKs and checksums in CI; install and smoke test pass on a clean device.
- Minified build passes the full smoke tests including the server jar.
- Docs match behaviour; no stale claims; privacy policy states exactly what data stays on device.

## Owner checks

- Create the signing key, store it in CI secrets and keep an offline backup. Decide the distribution channels.
