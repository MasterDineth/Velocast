# S08 Host app: Prepare and keep-alive

Depends on: S05, S06. Branch: step/S08-<name>.

Goal: The old-phone app verifies and fixes every prerequisite, keeps the phone reachable, and restores wireless debugging after a reboot where the platform allows.

## Prompt 8A: checklist engine and status

```text
Follow AGENTS.md. Step S08A, branch step/S08a-host-checklist. Work in :app-host (logic only; UI comes in S14). Read docs/product-requirements.md (RQ-02, RQ-05, RQ-07, RQ-10) and docs/findings.md (FUN-10, PERF-06).

1. Create ChecklistEngine with ChecklistItem(id, titleRes, reasonRes, check(): ItemState, fix(): FixResult, guide(): Intent?) where ItemState is Done, NeedsAction, Optional or Unknown. Items: DevOptionsEnabled (Settings.Global development_settings_enabled), UsbDebugging (adb_enabled), WirelessDebugging (adb_wifi_enabled), NoAuthTimeout (adb_allowed_connection_time == 0), StayAwakeWhileCharging (stay_on_while_plugged_in != 0), BatteryOptimisationOff (PowerManager), NotificationsAllowed, SecureSettingsGranted (WRITE_SECURE_SETTINGS), BootReceiverReady, WifiConnected, ChargingState, OptionalLauncherAvailable (Shizuku or root).
2. Fix paths: use WRITE_SECURE_SETTINGS directly when granted; otherwise return guide() intents to the right Settings screens (developer options, battery optimisation). Never fake success; always re-run check after fix.
3. Expose HostStatus as StateFlow (overall readiness, regressed items, address, method, last session, battery and charging). Persist the last known state so the status screen is instant.
4. Replace the 2-second su polling of the old DaemonController: status comes from the in-process engine and, for server state, from a local socket or Binder query to the server (not /proc scans or shell spawns).
5. Post a high-importance notification when an item regresses (for example wireless debugging switched off).
Tests: each item's check with a fake SettingsReader; engine state aggregation; regression notification logic.
Definition of done: :app-host:check passes; manual checklist for a real device in the PR; summary per AGENTS.md.
```

## Prompt 8B: keep-alive, boot recovery, pairing provider

```text
Follow AGENTS.md. Step S08B, branch step/S08b-host-keepalive. Work in :app-host. Read docs/security.md and the platform limits L2, L4, L10 in docs/product-requirements.md.

1. KeepAliveService: a foreground service with a valid foreground-service type for Android 14+ and a clear notification. While charging or while a session is active hold a Wi-Fi low-latency lock and the minimum wake handling needed; release both when unplugged and idle. Measure and record battery and thermal effect.
2. BootReceiver: handle both LOCKED_BOOT_COMPLETED (direct-boot aware, keep it minimal) and BOOT_COMPLETED. Once Wi-Fi is connected and WRITE_SECURE_SETTINGS is granted, set adb_enabled and adb_wifi_enabled via Settings.Global; retry with back-off for 10 minutes; record each attempt in a status log; then start the configured launcher (ADB-from-viewer needs nothing; Shizuku and root come in S09 and S10). Behave sensibly when the user has not unlocked after reboot.
3. PairingProvider: a ContentProvider whose call() accepts the pairing secret only when Binder.getCallingUid() is 2000 (shell) or 0 (root) AND a pairing window is open or no secret is stored. Store the secret with the Keystore-backed store from S06. Reject and log everything else. The viewer will call it with: content call --uri content://com.mastersoft.velocast.host.pairing --method setPairing --extra secret:s:<base64>.
4. Boot status: record whether wireless debugging came back, how long it took and why it did not.
Tests: provider caller checks (use a test that simulates calling uids), boot logic with fakes and a fake clock, service lifecycle.
Definition of done: :app-host:check passes; the PR lists the device checks for the owner (reboot, secure lock, unplug) and the observed results if available; summary per AGENTS.md.
```

## Acceptance criteria

- Every checklist item has a unit-tested check; items fixable with WRITE_SECURE_SETTINGS are fixed without user input once granted.
- After a reboot with Wi-Fi available, wireless debugging returns without touching the phone (device test), or the status says exactly why not.
- The pairing provider rejects callers other than uid 2000 or 0 (test).
- Keep-alive costs are measured: one hour on charge without throttling or battery drain beyond charging.

## Owner checks

- On a real old phone: run Prepare, reboot it, wait for Wi-Fi, and check the viewer can connect without touching the old phone. Repeat with a secure lock screen enabled and record what happens before first unlock.
