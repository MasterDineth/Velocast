# S16 Tests, security checks and device lab

Depends on: S14. Branch: step/S16-<name>.

Goal: A test suite and a repeatable manual rescue test plan that guard every earlier fix.

## Prompt

```text
Follow AGENTS.md. Step S16, branch step/S16-tests. Read docs/findings.md (CQ-01) and the acceptance criteria of every step in docs/steps.md.

1. Integration harness: a JVM or instrumented test that runs SessionGuard, the server pipeline (fake capture source) and SessionEngine over a loopback TCP proxy you control, adding configurable loss, delay, jitter and bandwidth caps. Scenarios: stall 1 s, drop 3 frames, link down 8 s, handshake attack, version mismatch.
2. Instrumentation smoke tests: viewer (add fake device, reach Viewer), host (checklist states with a fake SettingsReader). Configure Gradle managed devices and a CI job; keep it optional if runners cannot host emulators.
3. Security tests (script plus tests): connect without credentials and verify no data and no effect on an active session; fuzz the stream parser and the control channel with malformed lengths, pointer ids outside 0..31, huge config values and unknown types; replay and reorder captured encrypted frames; port scan during idle and during a session to prove only the intended port is open.
4. Soak and chaos scripts in tools/soak: Wi-Fi off and on, rotation 50 times, 500 connect/disconnect cycles checking for leaked descriptors, VirtualDisplays, codecs and threads, a 2-hour stream with periodic memory and thermal logging.
5. Write docs/device-lab.md (device matrix and setup) and docs/rescue-test-plan.md covering every scenario in docs/product-requirements.md with expected results and a results table template.
6. CI: unit and integration tests, lint, format, detekt, coverage report with a sensible threshold for :protocol and :client-core and :server-core, dependency and licence scan, and an artifact upload of test reports.
Definition of done: CI is green with the new jobs; docs written; list which acceptance criteria are covered by which test; summary per AGENTS.md.
```

## Acceptance criteria

- CI runs unit, integration and smoke tests on every pull request.
- Each acceptance criterion from S03 to S11 is covered by an automated test or a numbered manual test.
- Security tests prove the unauthenticated path is closed.

## Owner checks

- Run the manual rescue test plan on at least three phone models and record results in docs/rescue-test-results.md.
