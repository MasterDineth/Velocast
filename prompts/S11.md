# S11 Rescue session features

Depends on: S04, S07, S08. Branch: step/S11-<name>.

Goal: Make the session work with minimum input: wake, unlock, display control, keep-awake, typing, clipboard and auto-connect.

## Prompt 11A: wake, keep-awake, display power, unlock

```text
Follow AGENTS.md. Step S11A, branch step/S11a-rescue. Work in :server-core, :client-core and the protocol ACTION messages. Read docs/product-requirements.md (RQ-03, RQ-04, RQ-09), docs/findings.md (FUN-07) and docs/spike-shell-user.md.

1. Wake: ACTION_WAKE injects KEYCODE_WAKEUP (never a POWER toggle). On every connect, if the display is off, wake it; report SCREEN_OFF through STATUS when the display stays off.
2. Keep awake while streaming: add a server-side mechanism that works as the shell user (for example a wake lock or stay-on setting) and is removed on exit.
3. Display power: implement setDisplayPowerMode off/on through the safest per-API-level path (Android 14+ requires loading DisplayControl from the framework as scrcpy does; study the approach and write your own implementation with per-API handling). Keep capture running while the panel is off. Record state at session start and always restore it, including after a crash via the CleanUp helper.
4. Unlock helper (opt-in per device): detect keyguard state (IWindowManager or equivalent); sequence: wake, swipe up, enter PIN digits as key events, ENTER. Exactly one attempt per connect and no automatic retry (avoid lockout). The viewer stores the PIN encrypted with a Keystore key (optionally gated by biometric or device credential); send it only over the encrypted session; never log it; mask it in diagnostics. Show a clear warning that storing a PIN reduces security.
5. Protocol: add or confirm ACTION codes and STATUS flags (SCREEN_OFF, LOCKED) in :protocol with tests.
Tests: unit tests for the unlock sequencer with a fake injector (one attempt only, no logging of digits), display-power state restore logic, wake logic.
Definition of done: :server-core and :client-core checks pass; device test plan (PIN device, sleeping, display off, kill server) in the PR; summary per AGENTS.md.
```

## Prompt 11B: text, clipboard, auto-connect

```text
Follow AGENTS.md. Step S11B, branch step/S11b-input-connect. Work in :server-core, :client-core and :app-viewer (wiring only; screens come in S13). Read docs/product-requirements.md (RQ-01, RQ-06, RQ-08, RQ-12).

1. TEXT input: server types ASCII with key events using the virtual keyboard character map; for any non-ASCII text set the clipboard on the old phone and inject KEYCODE_PASTE. As the shell user, clipboard access needs a package identity; use the FakeContext approach from S05 and document the Samsung-specific behaviour you find.
2. Clipboard sync: viewer to old phone by default when the user pastes; old phone to viewer is opt-in. Both go over the encrypted session and are never logged.
3. Auto-connect: a ConnectionCoordinator in :client-core that picks the last used device (or the only ready one), starts the SessionEngine and keeps it alive across configuration changes. Support launch from an app shortcut, a Quick Settings tile and a notification action. With several devices show a chooser.
4. Reconnect integration: the coordinator observes SessionState and keeps trying for the configured window; it stops cleanly on user Disconnect.
Tests: text-to-key mapping tests (including characters needing shift), clipboard routing tests, coordinator tests with a fake engine and clock.
Definition of done: checks pass; device test plan (type a mixed Unicode string, paste, kill Wi-Fi) in the PR; summary per AGENTS.md.
```

## Acceptance criteria

- A sleeping, locked old phone is woken and (if the helper is on) unlocked by one tap with no more than one PIN attempt.
- Display-off works while capture continues and is restored on exit.
- Typing and paste work for ASCII and non-ASCII text.
- The PIN is never in logs, backups or screenshots and is protected by the Keystore (optionally biometric-gated).

## Owner checks

- Lock the old phone with a PIN, let it sleep, and connect: check wake, unlock helper, typing and display off. Try a wrong PIN once and confirm there is no automatic retry.
