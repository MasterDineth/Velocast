# S13 Viewer app UI

Depends on: S11, S12. Branch: step/S13-<name>.

Goal: A redesigned viewer: devices, one-tap connect, guided add, rescue guide, full-screen mirror, settings and diagnostics.

## Prompt 13A: navigation, home, add, prepare

```text
Follow AGENTS.md. Step S13A, branch step/S13a-viewer-ui. Work in :app-viewer using :designsystem and :client-core. Read docs/design-spec.md (viewer screens, navigation map, error catalogue).

1. Set up Compose Navigation with type-safe routes: Onboarding, Devices, AddDevice (QR, Code, USB), PrepareCheck, DeviceDetails, Connecting, Viewer, RescueGuide, Settings, Diagnostics. Bottom bar: Devices, Guide, Settings.
2. Create ViewModels exposing immutable UI state (StateFlow) built from DeviceStore and SessionState; side effects through a one-shot event channel. No business logic in composables.
3. Implement Onboarding (3 cards, skippable), Devices (cards with StatusChip and one primary Connect button, empty state, add button, auto-connect banner), AddDevice wizard with StepIndicator and the three pairing options (QR shown by the viewer for the old phone to scan; 6-digit code and port entry with validation; USB cable state from S07C), PrepareCheck showing the PrepareRunner results as ChecklistRows with Fix guidance for items needing the old screen, DeviceDetails.
4. Map every typed SessionError and pairing error to an ErrorPanel using the strings in docs/design-spec.md.
5. Handle windows of all sizes with WindowSizeClass (list-detail on large screens). Use edge-to-edge insets correctly on API 36.
6. Add navigation tests and ViewModel unit tests; add screenshot tests for each screen state.
Definition of done: :app-viewer:check passes; recorded manual walkthrough notes in the PR; summary per AGENTS.md.
```

## Prompt 13B: connecting, viewer, settings, rescue guide

```text
Follow AGENTS.md. Step S13B, branch step/S13b-viewer-ui. Work in :app-viewer. Read docs/design-spec.md.

1. Connecting screen: progress ring and ProgressSteps (Device found, Authenticated, Starting mirror, Waking screen) driven by SessionState; 20 s timeout shows the specific ErrorPanel; Cancel returns to Devices.
2. Mirror viewer: host the SurfaceView through AndroidView, letterbox using VIDEO_SIZE, immersive mode, optional HUD (off by default), floating ToolboxSheet (Back, Home, Recents, Wake, Screen off, Keyboard, Screenshot) with remembered position and 48 dp targets, a keyboard and paste sheet that uses TEXT and clipboard actions, banners for Screen off, Locked, Reconnecting (with countdown) and Paused. Pause on stop, resume on start. Keep the screen on while visible. Fix the screenshot feature to capture at stream resolution and to save correctly on API 26 to 36 (FUN-11).
3. Settings: auto-connect, keep old phone awake, quality (Auto, Balanced, Max), Unlock helper (PinPad setup, warning, remove), Diagnostics, Paired phones (revoke), About and licences. Replace the fabricated telemetry in the old settings preview with real or clearly labelled preview data (FUN-12).
4. Diagnostics: session timeline, last error, capability report, latency stats, Copy and Share with redaction of secrets and optionally IP addresses.
5. Rescue guide: the decision flow in docs/design-spec.md, an illustrated OTG-mouse walk-through, and honest limits; reachable from Home, from every error panel and from AddDevice.
6. Delete the legacy MirrorActivity, SettingsActivity and manual view code once the new screens are verified; remove dead resources and the exported-activity risk (SEC-08).
Tests: ViewModel unit tests, screenshot tests for each state, an instrumentation smoke test that launches the viewer, adds a fake device through a debug-only fake launcher and reaches the Viewer screen.
Definition of done: :app-viewer:check passes; manual walkthrough notes and TalkBack pass in the PR; summary per AGENTS.md.
```

## Acceptance criteria

- Every screen in the viewer spec exists with its states (empty, loading, error, success).
- One tap from Home to Connect for a paired phone; auto-connect works.
- All error panels map to the error catalogue with a single fix button.
- TalkBack walkthrough and 200 percent font pass; screenshot tests green.
- No business logic in composables; ViewModels are unit tested.

## Owner checks

- Walk the full flow with a fresh install: onboarding, pair, prepare, connect, rotate, background and return, error cases. Run Accessibility Scanner.
