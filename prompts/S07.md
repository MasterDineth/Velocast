# S07 ADB launcher and device store

Depends on: S05, S06. Branch: step/S07-<name>.

Goal: The viewer pairs with an old phone, connects, prepares it, pushes and starts the server and streams, with no root and nothing installed on the old phone.

## Prompt 7A: library decision, pairing, discovery, connect

```text
Follow AGENTS.md. Step S07A, branch step/S07a-adb-pair. Work in :launcher-adb. Read docs/spike-shell-user.md, docs/security.md, docs/findings.md (SEC-04, FUN-13).

1. Write docs/adb-library-decision.md comparing libadb-android, dadb (with a wireless-pairing-capable fork or extension) and a minimal in-house client for: wireless pairing and TLS support, USB transport, maintenance, licences (state exact licences and obligations), size, API level support. Recommend one with reasons and implement with it behind our own AdbClient interface so it can be swapped.
2. Implement AdbClient: generate and persist the client key pair and certificate in the Keystore-protected store; pair(host, port, code); pairWithQr(), which builds the standard ADB QR payload and advertises/accepts the pairing service so the old phone can scan it from Settings; connect(); shell(command); push(file, path); openStream(service).
3. NsdManager discovery for _adb-tls-pairing._tcp and _adb-tls-connect._tcp with timeouts and a manual host:port fallback. Handle the system choosing a new port each time wireless debugging is toggled.
4. Map failures to typed errors: DEBUGGING_OFF, DIFFERENT_NETWORK, AUTH_EXPIRED, NOT_PAIRED, wrong code.
5. Do not request ACCESS_LOCAL_NETWORK before targeting API 37 (FUN-13); keep the permission-handling in one place so it can be added later.
Tests: unit tests for the QR payload, error mapping and discovery state machine with fakes; a documented manual test plan for real devices.
Definition of done: pairing and connecting work against a real phone (owner verifies); docs updated; summary per AGENTS.md.
```

## Prompt 7B: launch, prepare, device store

```text
Follow AGENTS.md. Step S07B, branch step/S07b-adb-launch. Work in :launcher-adb and :client-core. Read docs/security.md and docs/spike-shell-user.md.

1. Implement AdbLauncher : ServerLauncher. Steps: connect; ensure the server jar on the device matches the SHA-256 of the bundled copy (push to /data/local/tmp/velocast-server.jar only if different, verify checksum after push); start with "CLASSPATH=/data/local/tmp/velocast-server.jar app_process / com.mastersoft.velocast.server.Main --port 0 --bind <wlan-ip> --secret-from-stdin"; write the per-session secret to stdin (never in argv); parse the READY line; return ServerEndpoint(host, port) and keep the shell stream open so the server dies with the session.
2. Provide the second data-channel mode: tunnel through an ADB stream (server bound to loopback) for USB and as a Wi-Fi fallback. Select automatically; expose the choice in diagnostics.
3. PrepareRunner: an ordered list of idempotent shell steps, each with check, apply and verify: settings put global stay_on_while_plugged_in 7; settings put global adb_allowed_connection_time 0 (disable the 7-day authorisation expiry); pm grant com.mastersoft.velocast.host android.permission.WRITE_SECURE_SETTINGS; cmd deviceidle whitelist +com.mastersoft.velocast.host; appops RUN_ANY_IN_BACKGROUND allow for the Host app. Each step reports Done, AlreadyDone, NeedsUser(reason) or Failed(reason). Flag any command that needs confirmation on a device you cannot test.
4. DeviceStore: encrypted persistence of Device(id, displayName, model, androidApi, lastAddress, adbKeyAlias, secretRef, method, lastSeen, preparedItems, hostAppVersion) with migration support and tests. Keep secrets only through the Keystore-backed store.
Tests: launcher flow with a fake AdbClient (checksum mismatch repush, READY parsing, timeout, secret never in argv), PrepareRunner step results, DeviceStore migrations.
Definition of done: a full session runs end to end against a real unrooted phone (owner verifies); summary per AGENTS.md.
```

## Prompt 7C: USB OTG transport

```text
Follow AGENTS.md. Step S07C, branch step/S07c-usb. Work in :launcher-adb. Read docs/adb-library-decision.md.
1. Implement an AdbUsbTransport using android.hardware.usb (UsbManager, UsbDeviceConnection, bulk endpoints of the ADB interface: class 0xFF, subclass 0x42, protocol 0x01). If the chosen library already supports USB, adapt it instead of writing your own.
2. Handle USB permission requests, device attach and detach broadcasts, the authorisation dialog case (AUTH_EXPIRED / needs on-device approval) and reconnecting after the old phone reboots.
3. Plug it into AdbLauncher so the viewer chooses USB automatically when Wi-Fi debugging is unavailable and an authorised cable is attached; tunnel the data channel through the ADB stream.
4. Add a clear UI-facing state (CableDetected, Authorising, Ready) for the Connecting and Add screens.
Tests: transport framing tests with a fake USB connection; manual test plan for two real phones, including a reboot of the old phone while connected.
Definition of done: session over a USB OTG cable works end to end on one phone pair (owner verifies); summary per AGENTS.md.
```

## Acceptance criteria

- Fresh viewer pairs and mirrors an unrooted old phone on Android 11 and 16 with no app installed on it.
- Prepare commands report per-item success or a typed reason.
- The viewer re-uses the stored authorisation after restart without prompting.
- USB OTG session works on at least one phone pair.

## Owner checks

- Pair with a real unrooted phone by QR and by code. Switch the old phone's Wi-Fi off and on and check rediscovery. Plug in an OTG cable and connect.
